# AI Assistant

AI Assistant формирует черновик персонального учебного плана только по
обезличенной аналитике попыток. Имя, email, логин, ответы ученика, правильные
ответы и тексты заданий во внешний API не отправляются.

## Режим по умолчанию

Без дополнительных настроек используется локальный бесплатный mock:

```env
AI_PROVIDER=mock
```

Он подходит для разработки, автоматических тестов и проверки интерфейса.

## Подключение YandexGPT

Для тестовой работы используется YandexGPT через Yandex AI Studio:

```env
AI_PROVIDER=yandex
YANDEX_AI_API_KEY=replace_with_yandex_api_key
YANDEX_FOLDER_ID=replace_with_yandex_folder_id
YANDEX_AI_MODEL=yandexgpt/latest
AI_REQUEST_TIMEOUT_MS=30000
```

Ключ хранится только в серверном `.env` и не имеет префикса `NEXT_PUBLIC_`,
поэтому не попадает в браузер. Провайдер всегда обращается к официальному
HTTPS API Yandex AI Studio. В запросе также отключается сохранение данных на
стороне провайдера через `x-data-logging-enabled: false`.

После изменения `.env` перезапустите `npm run dev`.

## Защитный контур

1. Платформа строит и проверяет обезличенную аналитику.
2. Провайдер получает только этот объект и методическую инструкцию.
3. Ответ разбирается как JSON.
4. План проходит строгую схему, ограничения количества тем, дней и задач.
5. Неправильный или слишком большой ответ отклоняется.
6. При ошибке внешнего API используется резервный mock.
7. Неудачная внешняя генерация и успешный fallback сохраняются в истории
   раздельно.
8. Учитель видит, каким провайдером создан конкретный план.

На текущем этапе доступны только `yandex` и `mock`. Если YandexGPT недоступен
или возвращает некорректный план, система автоматически использует mock.

## Рабочий цикл плана

1. Учитель вручную формирует новый AI-черновик в карточке ученика.
2. Учитель меняет заголовок, пояснение, темы, этапы, порядок и объём практики.
3. Кнопка «Утвердить и показать ученику» публикует проверенный план.
4. Ученик видит карточку на главной и подробную страницу `/student/study-plan`.
5. Кнопка этапа открывает тренажёр нужного номера с контекстом плана.
6. Каждая отправленная из плана попытка автоматически учитывается в прогрессе
   соответствующего этапа. Обычные попытки тренажёра продолжают попадать в
   общую аналитику, но не увеличивают прогресс конкретного плана.
7. Повторная генерация создаёт новый черновик и сохраняет предыдущие планы в
   истории. Ученик видит только опубликованные учителем планы.

Редактировать можно только черновик. После публикации его содержание
фиксируется, чтобы маршрут ученика и подсчёт этапов не менялись неожиданно.

## Проверка

```bash
npm run test:ai
npx tsc --noEmit
npm run lint
npm run build
```

Для проверки интерфейса на демонстрационных профилях:

```bash
npm run demo:ai:seed
npm run dev
```

Удаление только демонстрационных профилей:

```bash
npm run demo:ai:clear
```
