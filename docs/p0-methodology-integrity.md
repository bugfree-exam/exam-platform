# P0: методическая целостность заданий и освоения

## Неизменяемые версии заданий

- `Task` — постоянный логический идентификатор задания.
- `TaskRevision` — неизменяемый опубликованный снимок условия, справки, ответа, подсказки, решения и методических метаданных.
- Любое изменение содержимого или состава файлов создаёт новую ревизию и переводит `Task.currentRevisionId` на неё.
- `HomeworkTask`, `VariantTask`, `AttemptAnswer`, `PracticeAttempt` и `VariantAttemptAnswer` всегда хранят `taskRevisionId`.
- При первом назначении черновика ДЗ и первой публикации черновика варианта ссылки обновляются до актуальных ревизий, после публикации снимок больше не подменяется.
- Старые домашние работы, варианты и результаты читают содержимое только из сохранённой ревизии.
- Триггеры PostgreSQL запрещают обновление/удаление ревизий и изменение содержимого `Task` без одновременного переключения на новую ревизию.

## Материалы и подсказки

- `referenceHtml` доступен ученику до ответа и не должен содержать готовое решение.
- Файлы входят в снимок через `TaskRevisionAttachment`. Удаление файла из текущей версии не удаляет его из прошлых работ.
- `hintHtml` показывается после первой ошибки.
- После первой ошибки API возвращает `correctAnswer: null` и `explanationHtml: null`.
- Полное решение разрешено после верного ответа или повторной ошибки. В анонимном открытом банке решение после неверного ответа не раскрывается вообще.

## Независимое доказательство освоения

- Освоение учитывает только первую встречу ученика с логическим `taskId`.
- Повтор знакомого задания сохраняется в истории, но получает `countsForMastery = false`.
- Это правило одинаково для ДЗ, тренажёра и вариантов.
- Контроль спринта нельзя пройти на ранее встречавшейся задаче.

## Единая шкала mastery

Единственный источник порогов — `lib/mastery.ts`:

1. `INSUFFICIENT_DATA` — меньше 3 независимых попыток.
2. `CRITICAL_GAP` — точность ниже 40%, серия из 3 ошибок или значимое падение.
3. `PRACTICE` — точность от 40% до 64%.
4. `CONSOLIDATE` — точность от 65% до 84%.
5. `MASTERED` — точность от 85%.

Повторные решения не входят ни в объём, ни в точность, ни в прогресс «Ближайшего спринта».

## Проверка перед слиянием

Миграция предназначена для штатного production-safe применения через
`npx prisma migrate deploy`. Она не требует и не допускает `migrate dev` или
`db push` на боевой базе. Перед применением нужен актуальный резервный снимок
базы данных.

```bash
DATABASE_URL=postgresql://local:local@127.0.0.1:5433/exam_platform ./node_modules/.bin/prisma validate
./node_modules/.bin/tsc --noEmit
node --import tsx --test lib/ai/ai.test.ts
node --import tsx --test lib/p0-methodology.test.ts
npm run lint
npm run build
```
