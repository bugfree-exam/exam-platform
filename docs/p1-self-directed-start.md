# P1: самостоятельный старт внутри авторского годового курса

P1 разделяет общую программу преподавателя и персональную поддержку ученика. Платформа не генерирует каждому ученику собственную последовательность тем.

## Управление курсом

Страница `/teacher/course` позволяет преподавателю:

1. Создать один годовой курс с общими датами.
2. Собрать модули, указать номера ЕГЭ и расположить модули в методическом порядке.
3. Добавить на конкретные даты теорию, практику, ДЗ, вебинары, варианты, контроль и исправление ошибок.
4. Собрать единый входной контроль из конкретных заданий банка.
5. Расположить задания диагностики в нужном порядке, указать уровень и баллы.
6. Опубликовать неизменяемую версию диагностики.
7. Опубликовать курс и назначить его всем активным ученикам.

Новые ученики автоматически получают текущий опубликованный курс. Версия диагностики закрепляется в `StudentCourseEnrollment`: уже зачисленная группа остаётся на своей версии, а новые ученики получают последнюю опубликованную. Опубликованная диагностика хранит конкретные `TaskRevision`, поэтому редактирование задания в банке не меняет уже назначенный входной контроль.

Будущие модули и пункты курса можно корректировать. Прошедшие пункты расписания нельзя редактировать или удалять через API, чтобы история курса оставалась достоверной.

## Путь ученика

1. `/student/start` фиксирует личную цель, дату экзамена и реальный ресурс. Эти данные используются для аналитики и сигналов перегрузки, а не для перестановки тем.
2. `/student/diagnostic` показывает опубликованный учителем одинаковый разноуровневый контроль. Повтор знакомого задания не считается новым доказательством освоения.
3. `/student/route` показывает общий авторский курс, последовательность модулей и контрольные точки.
4. `/student/skills` показывает личное освоение и зависимости поверх общего курса.
5. Блок «Сегодня» содержит только `CourseScheduleItem`, назначенные преподавателем на текущую календарную дату по Москве.
6. Просроченные ДЗ и варианты вынесены в отдельный блок «Нужно обсудить или перепланировать» и не конкурируют с планом дня.
7. `/student/calendar` показывает общий график курса и отдельно персональные дедлайны.
8. Изменение личного ресурса создаёт запрос преподавателю. Оно не перестраивает годовой курс автоматически.
9. `/student/recovery` фиксирует одну цель и временный ресурс, сохраняя общий график видимым.
10. `/student/errors` продолжает полный цикл коррекции и отложенной проверки.

«Ближайший спринт» остаётся персональным педагогическим вмешательством. Он дополняет годовой курс, но не меняет его последовательность.

## Инварианты

- У курса один опубликованный общий маршрут.
- Порядок модулей определяет преподаватель; карта зависимостей не переставляет их автоматически.
- У каждой версии диагностики один состав, порядок и набор ревизий заданий для всех учеников.
- После завершения диагностики `StudentRoadmap` больше не генерируется.
- В «Сегодня» нет автоматически выбранных слабых навыков, долгов, ближайших вебинаров или AI-действий.
- Прошлое расписание и опубликованная диагностика защищены от редактирования.
- Ошибки, восстановление, аналитика и «Ближайший спринт» остаются персональными.

## Данные и развёртывание

P1 использует две последовательные миграции:

- `20260814190000_p1_student_journey` — старт, ошибки, восстановление и прежние P1-сущности;
- `20260815120000_p1_teacher_course` — годовой курс, календарь, назначения и версионируемый входной контроль.

В production применять только после резервной копии:

```bash
npx prisma migrate deploy
```

Миграция не удаляет старые `StudentRoadmap`: они остаются историческими данными, но больше не управляют ученическим интерфейсом.
